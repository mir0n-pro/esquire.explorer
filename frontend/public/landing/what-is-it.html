What is it?

Esquire is a business entity framework — the structural backbone for any system that needs to organize people, organizations, and resources in a tree, enforce who can see and do what within that tree, and run business operations against it.

Every framework promises that you write only business logic. That promise is kept when the parts it covers are in the box and already joined to each other — storage, identity and sign-in, permissions, the messaging between services, the audit trail, metrics, logs and traces. Esquire holds those, wired together and running, which is what leaves your domain as the only thing left to write. What it does not do is written down just as plainly.

Its authorization backbone is two dimensions at once: role-based rules for what a user may do, and tree-based scope for what a user may see — a user's position in the tree resolves both, with no per-query filter written by hand — and a filter nobody writes is a filter nobody can forget, which is the part that matters: elsewhere a query missing its scope looks exactly like a correct one. Any business domain can sit on top of it.

The backoffice scenario — onboarding, profile maintenance, permissions, accounting — is the demonstration domain. Accounting in particular is the "everybody's know-how" example: a universally understood domain that exercises the full framework stack end to end. It is the proof of the idea, not the destination.

Esquire is not a product you subscribe to. It is a framework you own, deploy, and extend. No SaaS lock-in, no monthly seat fees, no vendor standing between you and your data.

What it does not do

Esquire is a framework for developers building platforms. It is not a no-code tool and not a hosted service. It does not give you workflow automation, reporting dashboards or content management, and it is not an ERP — it is the structural layer such a product is built on. It does not replace your database, your message broker or your identity server; it brings them together into one working system.

The user interface it ships is the administration UI — the one that renders your entity descriptions at runtime, and at the same time the worked example of using the REST API. An application for your own end users is yours to write, against the same descriptions over the same API.

A mature framework — everything the stack makes possible

Esquire is not a prototype or a half-built foundation. It takes the ordinary, widely used technology stack — a relational database, Spring Boot, Node.js with Angular, the Grafana/Prometheus tooling — and delivers everything that stack makes possible, as one working system from database to browser. That is the whole cloud-native picture, not a slice of it: Esquire answers all fifteen factors of a modern cloud-native application — from API-first design through configuration, backing services, and disposability, to telemetry, authentication, and authorization. It already carries what most teams reach only years in:

  • High availability — every service runs redundantly, spread across nodes, so a lost pod or a lost node does not take the system down.
  • Full observability — metrics, logs, and distributed traces on one screen, joined by a single correlation id, so any request's whole story is one search away.
  • A hybrid REST + event-driven engine — synchronous APIs and an asynchronous messaging bus, both live, both vendor-neutral underneath.
  • Open at every layer — database, messaging transport, and identity are each a deployment choice behind a stable interface; no single vendor is baked in.
  • Running for real — the complete stack is deployed live in the cloud, not only on a developer's laptop.
  • One framework, more than one shape — the same code and settings run as eight programs or as five, so a small installation stops paying for a large one and nothing about the framework changes.

The three backbone ideas — tree-shaped visibility, positional authority, entity self-description — sit on a finished, production-grade cloud-native foundation. The floor is not just laid; it is complete.
